LINUX-NTFS AKMOD — PROCÉDURE DE MAINTENANCE
=============================================

Projet :
    linux-ntfs-akmod-dev

Source amont :
    Namjae Jeon's linux-ntfs

Branch :
    ntfs-next


1. MISE À JOUR UPSTREAM
-----------------------

Le mécanisme automatisé est assuré par :

    tools/auto-update-ntfs-next.sh

Le script vérifie le commit amont ntfs-next.

Lorsqu'un nouveau commit est disponible, il :

    - récupère le nouveau commit ;
    - crée/récupère l'archive SOURCE ;
    - met à jour le SPEC ;
    - synchronise l'environnement rpmbuild ;
    - construit les RPM ;
    - identifie déterministiquement le RPM akmod ;
    - installe le nouvel akmod ;
    - déclenche akmods.


2. IDENTIFICATION DU RPM AKMOD
------------------------------

L'identification du RPM akmod ne doit pas utiliser la date de
modification des fichiers.

Le script extrait du SPEC :

    AKMOD_NAME
    AKMOD_VERSION
    AKMOD_RELEASE
    AKMOD_ARCH

et construit :

    AKMOD_RPM="$RPMBUILD_TOPDIR/RPMS/$AKMOD_ARCH/$AKMOD_NAME-$AKMOD_VERSION-$AKMOD_RELEASE.$AKMOD_ARCH.rpm"

Le fichier est ensuite vérifié avant installation.

Cette identification déterministe est obligatoire pour
l'automatisation finale.


3. MISE À JOUR DU SPEC
----------------------

Modifier :

    SPECS/linux-ntfs-kmod.spec

Mettre à jour :

    Version
    Release
    Source
    %changelog

Chaque nouvelle version doit conserver une correspondance claire
entre :

    commit upstream
    archive SOURCE
    Version RPM
    Release RPM


4. CONSTRUCTION
---------------

Vérifier d'abord :

    /usr/bin/bash -n tools/auto-update-ntfs-next.sh
    /usr/bin/git diff --check

Construire :

    /usr/bin/rpmbuild -ba \
        "$HOME/rpmbuild/SPECS/linux-ntfs-kmod.spec"


5. AKMOD
---------

Installer le RPM akmod produit par la construction.

Puis vérifier :

    /usr/bin/rpm -q akmod-linux-ntfs

Forcer la génération pour le noyau courant si nécessaire :

    sudo /usr/bin/akmods \
        --force \
        --akmod linux-ntfs \
        --kernels "$(/usr/bin/uname -r)"


6. VÉRIFICATION DU MODULE
-------------------------

    /usr/bin/modinfo ntfs
    /usr/bin/modinfo -F vermagic ntfs
    /usr/bin/modinfo -F filename ntfs

Vérifier également :

    /usr/bin/lsmod | /usr/bin/grep '^ntfs '


7. MONTAGES NTFS
----------------

    /usr/bin/findmnt -t ntfs,ntfs3

Les partitions utilisant le pilote linux-ntfs doivent apparaître
avec :

    FSTYPE ntfs

et non :

    FSTYPE ntfs3


8. AUTOMATISATION SYSTEMD
-------------------------

Les unités du projet sont :

    tools/systemd/linux-ntfs-next-update.service
    tools/systemd/linux-ntfs-next-update.timer

Le timer actuel utilise :

    OnBootSec=15min
    OnUnitActiveSec=6h
    RandomizedDelaySec=30min
    Persistent=true

Vérifier :

    /usr/bin/systemctl --user status \
        linux-ntfs-next-update.timer \
        --no-pager

    /usr/bin/systemctl --user list-timers \
        linux-ntfs-next-update.timer \
        --no-pager

Le service doit terminer avec succès lorsqu'aucun nouveau commit
upstream n'est disponible.


9. RÈGLE IMPORTANTE
-------------------

Ne pas ajouter dans l'automatisation une recherche de RPM basée
sur :

    - la date de modification ;
    - -newer "$RPMBUILD_SPEC" ;
    - le dernier fichier trouvé dans RPMS/ ;
    - un glob ambigu pouvant correspondre à plusieurs RPM.

Le RPM akmod doit être identifié par les métadonnées du SPEC et
par le chemin déterministe AKMOD_RPM.


10. RESPONSABILITÉS
-------------------

L'orchestrateur est responsable de :

    - surveiller ntfs-next ;
    - récupérer la nouvelle source ;
    - mettre à jour le SPEC ;
    - construire le paquet ;
    - identifier et installer l'akmod ;
    - déclencher akmods.

Akmods est responsable de :

    - construire le kmod pour les noyaux concernés ;
    - gérer les kmods associés aux différents noyaux ;
    - maintenir la compatibilité avec les mises à jour du noyau.

Le projet ne doit pas revenir à une compilation manuelle de
ntfs.ko après chaque mise à jour du noyau.
